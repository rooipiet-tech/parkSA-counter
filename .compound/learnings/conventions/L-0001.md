statement: On touch UIs, committing an action on pointerdown (for sub-200ms feedback) silently converts any scroll gesture that begins on an interactive element into a phantom action. Give optimistic visual feedback on pointerdown but COMMIT the state change on pointerup only if the pointer stayed within ~10px slop and was not cancelled; revoke on pointercancel/large-move; set touch-action:none/manipulation on the interactive grid. Synthetic/dispatched tap events in a test harness never reproduce this — only a real touch-drag (CDP Input.dispatchTouchEvent swipe) does.
evidence: POL-01 blocker: CDP touch swipe starting on a tally tile drove queue 0->1 while the page scrolled; 71 unit + 37 e2e all passed because synthetic taps never scroll. POL-02 (12 tiles overflow 390x844 forcing mid-count scroll) made the hazard routine.
catch_next_time: Add a real-touch (CDP touch-swipe) e2e case: a swipe-scroll originating on every interactive element must produce zero state change. Treat 'commit on pointerdown' as a review red flag; require pointerup+slop commit for any counter/action control.
