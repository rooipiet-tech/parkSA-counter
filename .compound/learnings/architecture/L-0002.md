statement: A code path exercised only by a unit test that constructs the class directly can be entirely unreachable at runtime — no UI affordance and no agent/automation entry point wires it up. The test passes and the capability is a phantom. Every distinct state transition the spec requires must be reachable through the real product surface (a UI control AND/OR a documented programmatic method), and an e2e test must drive it through that surface, not by instantiating the implementation.
evidence: AN-01 (dup OR-F3) blocker: TapQueue.closeSessionRetroactively had zero runtime callers; never-ended sessions could only close as 'normal' with end_ts=now, silently marking an abandoned interval as covered. Only the agent-native parity lens caught it; the unit test hid it.
catch_next_time: Parity check: for each public capability, assert a runtime caller exists (UI testid or exposed API method) and that the e2e reaches it via click/API, never by newing the class. Flag any method whose only callers live in test files.
